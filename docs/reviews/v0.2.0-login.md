# Security review of login and access control (v0.2.0)

- **Reviewer:** a separate AI agent (Claude Opus) in a fresh context, told
  not to trust the author's comments, commit messages or PR text, plus an
  automated review of the pushed commit. Both reviewed branch
  `feat/oidc-login` (PR #20) on 2026-11-17.
- **Method:** the agent attacked the code from a separate crate depending on
  the repo by path, and ran the repo's own tests.
- **Status:** advisory (v0.x), recorded here with what was done.

## Held

- No library data without a session: 15 path variants with base `/lb`
  (dot segments, encoded dots, double slashes, trailing slash, the bare base,
  HEAD/OPTIONS/POST) all got a redirect to login, 401 or 404.
- No cross-person access: thumbnails, previews and originals filter by the
  viewer; viewer neighbours and prefetch stay in the viewer's libraries;
  EXIF is read only from the checked item; "all" needs more than one library.
- Token checks: unknown or replayed state is refused, PKCE is S256,
  issuer/audience/expiry/nonce are verified, and the key-rotation retry
  re-runs the full check.
- No secrets or tokens are logged.

## Found, and fixed before merge

| Finding | Severity | Fix | Test, planted fault |
|---|---|---|---|
| Login CSRF: the callback was not bound to the browser that started the login | medium | A random binding value is set as an HttpOnly cookie at `/auth/login` (Path `<base>/auth`, 10 min) and must match, compared in constant time, before the pending login is used. A foreign attempt does not consume it. | `a_callback_from_another_browser_is_refused`, `a_foreign_callback_does_not_burn_the_real_login`, F35 |
| Unauthenticated `/auth/login` grew the pending map without bound, `next` unbounded | medium | At most 1,000 pending logins (oldest evicted); `next` over 512 bytes is dropped | `pending_logins_are_capped_and_long_next_is_dropped`, F36 |
| A verified email could sign in as a person bound to a subject | low | Email matches only people configured without a subject | `email_does_not_override_a_configured_subject`, F37 |
| A cross-site form could sign people out | low | Logout refuses requests the browser marks cross-site (`Sec-Fetch-Site`) | `a_cross_site_logout_is_refused`, F38 |
| A double-encoded `..` in `next` left the base path (same host) | low | `next` with `%` or a `.`/`..` segment is dropped | `next_after_login_stays_in_the_app`, F40 |
| Token and key endpoints from discovery were not checked to be on the issuer's host (suspected) | low | Both must share the issuer's scheme, host and port | `endpoints_off_the_issuer_host_are_refused`, F39 |
| A failed discovery was retried on every login (suspected) | low | After a failure, 30 s without retrying | same test |

## Accepted, not changed

- Thumbnails and previews keep `Cache-Control: private, max-age=86400`, so
  they stay in a browser's cache after sign-out. Acceptable on the
  household's own devices; revisit if lichtbild is used on shared ones.
- Under a base path lichtbild shares an origin with the other apps on the
  same host: script on a sibling app could read lichtbild's pages with the
  user's cookie. This is architectural (one host for the house apps); the
  apps are the household's own.
- Not checked: the real provider's behaviour (whether `email_verified` can be
  self-asserted, code lifetime) and normalisation in the reverse proxy.
  People are mapped by subject, which is not user-editable.
